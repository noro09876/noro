# Архитектура PhotoAgent

```
Браузер (web/: index.html, app.js) ──HTTP──► server.py (FastAPI, только 127.0.0.1)
                                               │
                                               ▼
                                   jobs.py — JobManager
         загрузка (файлы/папки/ZIP) · референсы · очередь · пауза/отмена · ZIP · отчёт
                                               │ один фоновый поток, кадры строго по одному
                                               ▼
interpreter.py ──► planner.py ──► pipeline.py ──► ops/* (операции) ──► qc.py ──► повтор с поправками
 (текст → TaskSpec)  (порядок шагов,  (кадр: шаги → сохранение                 (проверки → Issue{fix})
                      проверки        → контроль → повтор)
                      моделей/реф.)
                                               │
                 models.py (реестр весов, ModelCache)      comfy.py (локальный ComfyUI по HTTP)
                 storage.py (SQLite: задания, кадры, журнал)  imageio.py (чтение/запись без потерь)
```

## Модули

| Модуль | Ответственность |
|---|---|
| `server.py` | HTTP API и раздача интерфейса |
| `jobs.py` | задания, загрузка, очередь и фоновый обработчик, предпросмотр, повторы кадров, ZIP, отчёт |
| `interpreter.py` | русский текст → `TaskSpec` (операции, параметры, что сохранить, экспорт); непонятые фразы возвращаются отдельно; Ollama по желанию |
| `planner.py` | `TaskSpec` → упорядоченный план; заранее сообщает, каких моделей, референсов или ComfyUI не хватает |
| `ops/` | операции; каждая регистрируется декоратором `@register` |
| `pipeline.py` | обработка кадра: шаги, промежуточные файлы, контроль качества, повтор со снимка состояния |
| `qc.py` | проверки качества; каждая проблема может нести поправку `fix` для повтора |
| `models.py` | реестр весов: источник, SHA-256, лицензия; кэш сессий с выгрузкой из памяти |
| `comfy.py` | клиент ComfyUI: проверка узлов и моделей, граф FLUX.2 klein, ИИ-увеличение, выгрузка памяти |
| `storage.py` | SQLite: задания, кадры, референсы, журнал. Это источник правды для возобновления |
| `imageio.py` | float32 RGB + альфа; EXIF-поворот, ICC, 16 бит, атомарная запись |

## Как добавить новую операцию

1. Создайте класс в `ops/` с `id`, `title`, методом `run(ctx, params)` и декоратором `@register`. Если операции нужны референс, модель или ComfyUI, укажите `needs_refs`, `models` или `needs_comfyui`.
2. Добавьте её id в `planner.ORDER` на нужное место.
3. Добавьте правило в `interpreter._apply_rules` для русских формулировок.
4. По желанию добавьте проверку в `qc.py` с поправкой `fix` и перечислите в операции `fix_keys`. Тогда при повторе обработка продолжится с этой операции, а не с начала.

Новая модель добавляется записью в `models.MODELS`, без изменений в остальном коде.

## Ключевые решения

- **Без PyTorch в основном приложении.** На RTX 50xx нужны сборки PyTorch с CUDA 12.8 и новее, а лишний PyTorch занимает гигабайты. Нейросети маски и лиц работают через ONNX Runtime (на Windows через DirectML на видеокарте). Тяжёлые генеративные модели работают в отдельном ComfyUI, который сам управляет видеопамятью и выгрузкой в ОЗУ.
- **Один кадр за раз.** В памяти держится только текущий кадр и не больше одной тяжёлой модели. После задания модели выгружаются, ComfyUI получает команду `/free`.
- **Личность защищена устройством пайплайна, а не надеждой на модель.** При замене одежды в кадр переносится только область одежды, а лицо, причёска и кожа копируются из исходника. Затем проверка SFace сравнивает лицо с оригиналом.
- **Детерминированный разбор заданий.** Одно и то же задание всегда даёт один и тот же план, без затрат на языковую модель и без интернета. Непонятное показывается пользователю, а не угадывается.
- **Ограниченные повторы.** Не больше 2 повторов (`Settings.max_quality_retries`). Повтор запускается, только если поправка влияет хотя бы на один шаг. Из всех попыток сохраняется лучшая.
- **Оригиналы неприкосновенны.** Загрузки копируются в `originals/` и помечаются «только чтение». Результаты пишутся в другие папки, запись атомарная.
