# Предложение заказчику: Motion DNA

## Что продаём

Не шаблоны, не промпты и не репозиторий, а **язык описания моушн-стиля и словарь приёмов в виде данных**, которые их агент читает так же, как сейчас читает таймлайн:

1. **Формат стиля** (`motion-dna/spec/motion-style.schema.json`): типографика по ролям, раскладка с безопасными полями, ритм (склейки и вход текста относительно речи и долей), вход и выход текста, акценты, плашки, переходы, камера, финиш, анти-шаблонные правила (`humanize`, `bans`).
2. **Библиотека приёмов** (`motion-dna/library/techniques.json`): каждый приём — ключевые кадры, кривые, параметры с диапазонами, точка удара под звук, аудио-якорь и рейтинг узнаваемости `ai_tell`. Сейчас 28 приёмов, по договору — 60+.
3. **Разборы референсов**: ссылка на рилс → `style.json` с уверенностью по каждому разделу и покадровым сравнением (протокол — `motion-dna/ANALYSIS.md`).
4. **Бонус для их разработчика**: эталонный компилятор правил на Python (без зависимостей) и анализ звука на numpy. Их можно взять как есть или использовать как исполняемую документацию: «вот как правило превращается в кадры».

Почему это решает их проблему «не должно быть видно, что монтировала нейросеть»: агент не сочиняет анимацию, а выбирает приём из словаря в разрешённых диапазонах. Приёмы-маркеры «ИИ-видео» запрещены по умолчанию, человеческая неровность задана правилами и воспроизводима по `seed`.

## Как продаём

1. **Отклик**: ответы на 3 вопроса (ниже), два ролика, ссылка на формат и библиотеку.
2. **Бесплатный тест за 2 рабочих дня**: они присылают mp4 референса (например, того рилса из вопроса 2) и один свой смонтированный рилс без моушна. Мы отдаём `style.json`, рендер их ролика в этом стиле и сравнение «референс / наш рендер» в 6 ключевых моментах. Это снимает главный риск для них: они видят результат на своём материале до оплаты.
3. **Этапы с фиксированной ценой**:
   - этап 1 — формат v1, библиотека из 60+ приёмов, 5 разборов референсов, созвон с их разработчиком по контракту плана;
   - этап 2 — ещё 15 разборов, калибровка по их рендерам (сравниваем их выход с референсом и правим параметры), правила для их базы футажа;
   - поддержка — разбор новых референсов поштучно.
4. **Критерии приёмки** (измеримые, прописать в договоре): стиль проходит валидацию; склейки на тех же долях, что в референсе, ±1 кадр; покадровое совпадение в 6 моментах; слепой тест «человек или ИИ» на их команде.

## Ответы на типичные возражения

- *«Нам не нужны репозитории и код»* — основной результат — два JSON-файла и документация. Код — референс, его можно не брать.
- *«У нас Python, не JS»* — компилятор и анализ звука на Python. Remotion — только наш инструмент для превью (бесплатен для команд до 3 человек, компаниям нужна лицензия, поэтому встраивать его не предлагаем).
- *«Узнаваемые ИИ-стили»* — у каждого приёма есть рейтинг `ai_tell`, приёмы с `high` запрещены валидатором, плюс бюджет акцентов, запрет повторов и разброс таймингов.

## Что нужно сделать перед отправкой

- **Вопрос 1.** Залить `motion-dna/renders/*.mp4` туда, откуда заказчик сможет их посмотреть, и вставить ссылки. Не называть их «по референсу из Instagram»: референс — наши стилевые файлы, и в тексте отклика это сказано прямо.
- **Вопрос 2.** Рилс по ссылке посмотреть не удалось: из этой облачной сессии Instagram недоступен. Описание нужно сделать по самому ролику, а не по догадке. Варианты: посмотреть его и заполнить 7 строк по шаблону; прислать mp4, и разбор сделаем по протоколу с замерами; или разрешить домен instagram.com в сетевых настройках окружения.
