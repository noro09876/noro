# Архитектура NORO

## Принципы

1. **Всё полезное работает без сервера.** Шесть продуктов — клиентские приложения: разбор файлов, проверки, скоринг, поиск, аналитика выполняются в браузере. Ключи API не нужны.
2. **Файлы пользователя не покидают браузер.** Сетевые запросы делает только форма заявки (`/api/lead`) и, если владелец сайта включил модель и посетитель сам включил опцию, Support (`/api/ai`). Это проверяется e2e-тестами: любой запрос за пределы сайта роняет тест.
3. **Честность.** Локальные алгоритмы так и называются. Где нужна внешняя интеграция, интерфейс показывает метку «Требует подключения», а не имитацию.
4. **Логика отдельно от интерфейса.** У каждого продукта есть `logic/` с чистыми функциями и unit-тестами и `ui/` с React-компонентами.

## Слои

```
Браузер
├── Сайт (React 19 + react-router 7)
│   ├── pages/        Главная, Продукт (/products/:slug), Контакты, Политика, 404
│   ├── components/   дизайн-система: ui · app · charts · site · home
│   └── products/     6 приложений, каждое — отдельный lazy-чанк
│       ├── logic/    чистые функции (импорт, проверки, алгоритмы) + *.test.ts
│       └── ui/       вкладки, состояние, экспорт
├── lib/              CSV (papaparse), XLSX (read-excel-file, лениво), PDF (pdf.js, лениво),
│                     валидаторы (ИНН/КПП/БИК/счёт/EAN), текст (токенизация, стемминг RU),
│                     IndexedDB / localStorage, выгрузка файлов
└── hooks/            useIdbState (IndexedDB с отложенной записью), useUndo, useSeo …

Netlify
├── статические файлы dist/ (пререндеренный HTML для каждого маршрута)
└── Functions (src/server → netlify/functions)
    ├── /api/lead       валидация → Telegram и/или вебхук; 503, если не настроено
    └── /api/ai(/status) ответ Support строго по источникам через Anthropic API
```

## Маршруты и SEO

`scripts/postbuild.mjs` после сборки создаёт `dist/<маршрут>/index.html` для всех страниц с собственными `<title>`, description, canonical, Open Graph и текстом в `<noscript>`, а также `404.html`, `sitemap.xml`, `robots.txt`. Netlify отдаёт эти файлы напрямую, поэтому:

- прямые ссылки и обновление страницы работают без catch-all редиректа;
- несуществующие адреса получают настоящий статус 404;
- у каждой страницы своё превью в мессенджерах (`public/og/*.png`).

## Хранение данных

- **IndexedDB** — наборы данных и состояние продуктов (`<продукт>:state`, `business-intelligence:data` и т. д.). Запись откладывается на 400 мс; при уходе со страницы несохранённое значение пишется немедленно, а для перезагрузки дополнительно делается синхронная страховочная копия в `localStorage` (до ~3 МБ), которая подхватывается при следующем открытии.
- **localStorage** — небольшие настройки.
- **Сброс** — кнопка в каждом продукте вызывает `clearProductData(<продукт>)` с подтверждением.
- **Отмена** — `useUndo` для массовых операций (Lead Engine, Catalog Studio), тосты «Отменить» для удаления и правок (Docs Intelligence), версии черновиков (Content OS).

## Импорт файлов

`lib/files.ts` проверяет расширение, размер (лимиты 0,5–15 МБ в зависимости от продукта) и «бинарность» текста; `lib/tabular.ts` определяет кодировку (UTF-8 / Windows-1251), разделитель, заголовки; `MappingDialog` даёт подтвердить сопоставление колонок. Ошибки показываются текстом, без падения приложения. PDF-разбор и XLSX подгружаются только при необходимости.

## Безопасность

- `netlify.toml`: строгая CSP (`default-src 'self'`, без `unsafe-inline`), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS, COOP.
- Пользовательский текст выводится только через React (без `dangerouslySetInnerHTML`); HTML-отчёт BI экранирует значения и не содержит скриптов.
- CSV-выгрузки защищены от формул (`=`, `+`, `-`, `@` в начале ячейки).
- Секреты только в переменных окружения функций. Функции проверяют размер и формат входа, у `/api/ai` и `/api/lead` настроены лимиты частоты запросов Netlify.

## Языковая модель (необязательно)

`src/server/ai.ts` использует официальный SDK `@anthropic-ai/sdk`: модель `claude-opus-5-5` (переопределяется `AI_MODEL`), `output_config.effort: "low"`, серверные фолбэки (`fallbacks: "default"`), проверка отказа модели (`stop_reason: "refusal"`). Вопрос и найденные локальным поиском статьи передаются как данные в тегах `<question>`/`<source>`; системная инструкция запрещает добавлять факты вне источников. Клиент вызывает модель, только если `/api/ai/status` сообщает, что ключ настроен, и посетитель включил опцию в настройках Support.

## Тесты

- `vitest` — логика продуктов, валидаторы, парсеры, функции Netlify (с подменой сети и SDK).
- `playwright` — e2e на собранном сайте через `scripts/serve-dist.mjs`, повторяющий поведение Netlify; аудит доступности (axe), вёрстки (320–1440 px, все вкладки), производительности, сдвигов макета, большого объёма данных.
