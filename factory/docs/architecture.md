# Архитектура NORO AI Content Factory

## Компоненты

```
web/ (React 19, Vite)  ──HTTP──▶  server/http (Fastify 5)  ──▶  Postgres (Drizzle, миграции)
                                        │                           ▲
                                        └─ enqueue ─▶ pg-boss ──────┤
                                                        │           │
                                     server/jobs (воркер) ─────────┘
                                        ├─ pipeline: стратегия → тексты → дизайн → видео → проверки
                                        ├─ render: Remotion (слайды, графика, видео 9:16/1:1/16:9)
                                        ├─ providers: LLM / изображения / озвучка
                                        ├─ publisher: адаптеры 7 API-площадок + ручной режим
                                        └─ maintenance: метрики, обновление токенов, очистка
```

- **API и воркер** — один код, два режима запуска. `INLINE_WORKER=1` запускает воркер внутри
  API (удобно для одного сервера), `npm run start:worker` — отдельным процессом.
- **Очередь** — pg-boss в той же базе. Очереди: strategy, generate, design, video, publish,
  metrics, maintenance. Ограничения параллельности: видео 1, дизайн 1, генерация 3, публикация 2.
- **Хранилище файлов** — локальная папка или любое S3-совместимое (AWS, Yandex Object Storage,
  MinIO, R2). Доступ к файлам только участникам пространства; для внешних площадок —
  подписанные ссылки с ограниченным сроком.

## Конвейер (9 стадий)

Идея → Стратегия → Генерация → Дизайн → Проверка → Согласование → Планирование → Публикация → Аналитика.
Статусы рейки не декоративные: они вычисляются из материалов, проверок, согласований и
публикаций в базе (`server/pipeline/stages.ts`).

1. **Стратегия**: LLM возвращает JSON по zod-схеме (позиционирование, рубрики, ключевые сообщения,
   план). План нормализуется под выбранные площадки и форматы и ограничивается лимитом пространства.
2. **Генерация**: каждый слот плана — отдельный материал с версиями. Перегенерация может касаться
   всего материала, одного слайда, сцены или поля; старые версии хранятся, есть сравнение и откат.
3. **Дизайн**: карусели и графика рендерятся Remotion в фирменных цветах и шрифтах бренда.
4. **Видео**: сценарий → озвучка по сценам (Piper/OpenAI/ElevenLabs) → точная временная шкала →
   субтитры (VTT/SRT, по словам) → рендер MP4 с анимированным интерфейсом и обложкой.
5. **Проверка**: обязательные поля, запрещённые формулировки бренда, заглушки, лимиты площадок
   (длина, формат, длительность и размер видео). Ошибки блокируют согласование.
6. **Согласование** привязано к конкретной версии: новая версия отменяет ожидающее согласование.
7. **Планирование**: проверка конфликтов (тот же аккаунт ближе 60 минут, суточный лимит площадки),
   переопределение только явным «всё равно запланировать». Время хранится в UTC, вводится в поясе кампании.
8. **Публикация**: планировщик раз в минуту ставит в очередь посты, у которых наступило время.
   Публикатор захватывает пост условным UPDATE, повторно проверяет согласование и версию,
   вызывает адаптер площадки. Ошибки: временные — повтор через 1, 4, 16, 64 минуты (до 3 часов,
   с учётом Retry-After); постоянные — сразу «ошибка» с понятным текстом; при отзыве токена —
   одна попытка обновления. Прерванная отправка становится «результат неизвестен».
9. **Аналитика**: раз в 6 часов собираются метрики опубликованных постов там, где API их отдаёт.
   Недоступные метрики так и показываются: «площадка не отдаёт», без подстановки чисел.

## Автоматизация

Правило задаёт расписание, количество и форматы, площадки, режим согласования и слоты публикации.
Запуск правила создаёт обычную кампанию и проходит тот же конвейер. Защита:
лимиты запусков и материалов в сутки, пауза после N ошибок подряд, подтверждение (HTTP 428)
при включении правила без согласования человеком или с крупными объёмами.

## Безопасность

- Сессии: случайный токен в httpOnly-cookie, в базе только его sha256, срок 30 дней.
- CSRF: все изменяющие запросы `/api/*` требуют заголовок `x-requested-with: noro`.
- Роли: owner, admin (всё), editor (правка, публикация), approver (согласование), viewer (чтение).
  Демо-пространство только для чтения у всех.
- Секреты: AES-256-GCM, маскирование в ответах, редактирование полей в логах и очистка
  токенов из текстов ошибок внешних API.
- Заголовки: CSP, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`; ограничение частоты
  запросов (общее и отдельное для входа и регистрации).

## Данные

Ключевые таблицы: `workspaces`, `memberships`, `brands`, `provider_configs`, `campaigns`,
`pipeline_stages`, `content_items`, `content_versions`, `assets`, `quality_checks`, `approvals`,
`social_accounts`, `platform_posts`, `publish_attempts`, `post_metrics`, `automation_rules`,
`audit_log`, `usage`. Миграции — `server/db/migrations`, применяются при старте.

Демо-данные отделены флагом `is_demo` на всех уровнях; планировщик и публикатор их пропускают,
а аналитика исключает.
